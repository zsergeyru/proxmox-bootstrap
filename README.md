# Публичный загрузчик Proxmox

Этот репозиторий содержит только первоначальную точку входа для проекта [zsergeyru/proxmox](https://github.com/zsergeyru/proxmox).

`bootstrap-pve.sh` загружает `bootstrap-pve.py`. Публичный код проверяет минимальные условия на PVE, создаёт временный контейнер **990**, получает основной проект и передаёт ему выполнение. Публичный загрузчик **не определяет постоянных гостей, их роли, состояние и порядок обслуживания**.

## Запуск

От `root` на физическом PVE:

```bash
curl -fsSL https://raw.githubusercontent.com/zsergeyru/proxmox-bootstrap/main/bootstrap-pve.sh | bash
```

При первом запуске может быть создан SSH-ключ только для чтения репозитория. Загрузчик покажет его **открытую часть** и прекратит работу до создания 990. Добавьте этот ключ к `zsergeyru/proxmox` с правом только на чтение и повторите команду.

Для запуска нужны доступная сеть, хранилища Proxmox, шаблон Debian 13 (либо возможность его получить) и доступ к GitHub.

## Разделение ответственности

```text
PVE
  → bootstrap-pve.sh / bootstrap-pve.py
  → временный LXC 990
  → получение zsergeyru/proxmox
  → scripts/bootstrap-runner/bootstrap-host.py
  → определение роли и проверка состояния в основном проекте
  → выполнение выбранного сценария
```

Публичный загрузчик управляет **только своим временным 990**. При каждом запуске он создаёт чистый 990: если временный контейнер остался от предыдущего запуска, загрузчик сначала проверяет его принадлежность и отсутствие дополнительных подключений, затем останавливает и удаляет его. Чужой или изменённый контейнер автоматически не удаляется; загрузчик сообщает причину и необходимое действие. Наличие других VM/LXC не служит причиной для отказа ещё до запуска 990: проверка принадлежности и состояния постоянных объектов выполняется после получения основного проекта, в закрытом сценарии.

Публичный запуск **не является командой повседневного обслуживания** и сам не разрешает разрушительное восстановление существующих объектов. Внутренний режим восстановления передаётся только штатным аварийным помощником основного проекта. Для проверок, ремонта, обновления и восстановления используйте операторские команды, описанные в [основном проекте](https://github.com/zsergeyru/proxmox/blob/main/docs/800-operations/830-recovery.md).

После успешного завершения закрытый сценарий удаляет временный 990 и его доступы. При ошибках временный контейнер может оставаться для диагностики.

На PVE не устанавливаются Docker, Semaphore, OpenTofu, Ansible или Packer.

**Ограничение проверок:** автоматические испытания исходного кода не заменяют проверку полного развёртывания на отдельном PVE.
