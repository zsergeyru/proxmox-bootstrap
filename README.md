# Первоначальная установка Proxmox

Публичный репозиторий содержит **только точку входа для первоначальной установки** проекта [zsergeyru/proxmox](https://github.com/zsergeyru/proxmox).

`bootstrap-pve.sh` загружает `bootstrap-pve.py`. Публичная часть подготавливает временный контейнер **990**, получает проект и передаёт ему настройку управляющего контейнера **910**.

## Установка

Выполните от `root` на физическом PVE:

```bash
curl -fsSL https://raw.githubusercontent.com/zsergeyru/proxmox-bootstrap/main/bootstrap-pve.sh | bash
```

Установщик сам определяет нужный сценарий:

- **910 отсутствует, постоянного состояния нет** — первоначальная установка с созданием 910.
- **910 отсутствует, постоянное состояние сохранено** — восстановление с обязательной предварительной проверкой данных. При неполных данных выполнение прекращается без создания пустого состояния поверх старого.
- **910 уже существует** — установка прекращается **до подготовки 990**, без пересоздания 910 и изменения его постоянных данных.

На первом запуске может быть создан SSH-ключ чтения GitHub. Установщик покажет его **открытую часть** и завершится до создания 990. Добавьте этот ключ к репозиторию `zsergeyru/proxmox` с правом только на чтение, затем повторите ту же команду.

Для первоначальной установки необходимы работающая сеть, хранилища PVE, доступный Debian 13 и доступ к GitHub.

## После установки

Для обслуживания и восстановления используется **одна операторская команда на PVE** — `infra-manager`:

```bash
infra-manager status
infra-manager deploy 910
infra-manager repair
infra-manager recover
```

- `status` проверяет работоспособность управляющего контура.
- `deploy 910` выполняет штатное обновление.
- `repair` исправляет неисправности без пересоздания 910.
- `recover` — аварийное пересоздание 910, в том числе при повреждённом системном разделе. Оно выполняется через независимый помощник на PVE и сохраняет обязательное постоянное состояние.

**Не используйте публичный установщик для проверки, удаления или обслуживания работающего 910.** Внутренний механизм восстановления вызывается только штатной командой `infra-manager recover`.

## Устройство

```text
Публичная установка с PVE
  → короткий загрузчик bootstrap-pve.sh
  → bootstrap-pve.py
  → временный контейнер 990
  → получение проекта zsergeyru/proxmox
  → закрытый сценарий первоначальной настройки
  → управляющий контейнер 910
  → проверка готовности и удаление 990
```

Временный 990 не хранит постоянное состояние. На физический PVE не устанавливаются Docker, Semaphore, OpenTofu, Ansible и Packer: они работают внутри соответствующих контейнеров.

Подробные правила восстановления, проверки сохранности данных и эксплуатации находятся в [документации основного проекта](https://github.com/zsergeyru/proxmox/blob/main/docs/800-operations/830-recovery.md).

**Ограничение проверок:** автоматические испытания исходного кода не заменяют проверку полного развёртывания на отдельном настоящем PVE.
